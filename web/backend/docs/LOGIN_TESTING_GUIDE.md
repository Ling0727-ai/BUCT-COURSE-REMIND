## 🐛 已知问题和解决方案

### 问题1: 邮件发送失败

**现象:** 提示"邮件服务暂时不可用"

**解决方案:**

1. 检查 `.env` 文件中的 `MAIL_PASSWORD`
2. 确认使用的是授权码而非登录密码（163邮箱）
3. 查看日志中的详细错误信息

### 问题2: 用户名未显示

**现象:** 邮件或页面中没有显示用户名

**可能原因:**

1. 邮箱未注册 → 正常，会显示提示联系管理员
2. 数据库中用户没有用户名字段 → 检查数据库

### 问题3: 邮箱登录不成功

**现象:** 使用邮箱登录提示账号不存在

**检查:**

1. 确认该邮箱已注册
2. 检查数据库中 email 字段的值
3. 查看后端日志

## 📊 性能影响

### 登录性能

- 原本：1次数据库查询（用户名）
- 现在：最多2次数据库查询（用户名 + 邮箱）
- 影响：可忽略（只在用户名未找到时才查询邮箱）

### 邮件发送

- 新增：1次数据库查询（查找用户名）
- 影响：可忽略（已有邮箱查询的场景）

## 🔒 安全性

### 用户名泄露风险

**缓解措施:**

1. ✅ 只在验证邮箱所有权后显示用户名
2. ✅ 需要输入正确的验证码
3. ✅ 有发送频率限制（1分钟1次）
4. ✅ 验证码有效期短（3分钟）

### 账号枚举

**现状:**

- 错误提示不透露账号是否存在
- "账号不存在，请检查用户名或邮箱"（不区分是用户名还是邮箱不存在）
